### 3.2 Test suite — 2 failures at baseline

The suite is **not green at the pinned commit on this platform.**

```
--- FAIL: TestBuildRestore_HostileFilenamesRoundTrip (0.02s)
    tar_names_test.go:80: cannot stage "tab\there.txt": open ...\005\tab	here.txt:
    The filename, directory name, or volume label syntax is incorrect.

--- FAIL: TestBuildFilelist_IsNulDelimited (0.02s)
    tar_names_test.go:145: cannot stage "tab\there.txt": open ...\005\tab	here.txt:
    The filename, directory name, or volume label syntax is incorrect.
```

Single shared root cause, and it is a **test-portability defect, not a product defect**.
`hostileNames()` at `tar_names_test.go:31` places `"tab\there.txt"` in the unconditional fixture
list at line 39, while the `runtime.GOOS != "windows"` guard at line 41 protects only the
newline-bearing names and the over-260-character path. A TAB is not a legal Win32 filename
character, so `os.WriteFile` fails and the `t.Fatalf` at line 68 aborts both tests before any
product code runs.

Consequence worth stating plainly: these two tests are the regression coverage for the
NUL-delimited tar work in commit `2cf3181` (OB-008). **That fix is therefore unverified on
Windows** — the tests proving it cannot execute there. CI runs `ubuntu-latest` only
(`.github/workflows/ci.yml:9`), so this has never been caught. Filed as OBX-001.

**Blocker:** `-race` on windows/amd64 requires cgo plus a C toolchain. `gcc` is absent, and this

CI does run it — `.github/workflows/ci.yml:42` executes `CGO_ENABLED=1 go test -race ./...` on
`ubuntu-latest`. That is race evidence for Linux at whatever commit last ran, and it is not
evidence for windows/amd64, nor for the Windows-only files (`dirsync_windows.go`,

Independently of any run: **a passing race result is evidence about the schedules that run
exercised, not proof that the concurrency design is sound.** See OB-007 in `OB_STATUS.md` for
ownership defects that are real regardless of what the detector reports.

### 3.6 Pictograph check — FAIL on tracked source

The allow-list script documented in `docs/CONTRIBUTING.md` permits only ✓ and ✗ as pictographs,
plus a named typography set. Two problems surfaced.

First, the script as written **crashes on Windows** before completing: it prints matched lines to
a cp1252 console and dies with `UnicodeEncodeError` on the first character outside that codepage.
It needs `PYTHONIOENCODING=utf-8` (or an explicit `reconfigure`) to run to completion here. Filed
as OBX-003.

Second, once it runs, it flags three lines in tracked source:

| Anchor | Character | Context |
|---|---|---|
| `ui/index.html:3214` | U+2715 MULTIPLICATION X | Should be ✗ U+2717, the only permitted failure mark |
| `bagit.go:48` | U+00A7 SECTION SIGN | In an RFC 8493 citation comment |
| `pipeline.go:502` | U+2208 ELEMENT OF | In the `ScanProblem` doc comment |

Scope breakdown: tracked `docs/**/*.md` is clean (21 files, 0 flagged). The untracked handoff
bundle contributes 144 flagged lines across 77 files — expected, and it must stay unmodified,
but it means the documented one-liner cannot be run as-is while the bundle is extracted in-tree.
Filed as OBX-002.

This check is **not** enforced in CI; only the advisory `prose-lint` step runs there.
